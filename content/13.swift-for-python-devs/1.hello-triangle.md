# Tutorial 1: Hello Triangle

The graphics programming equivalent of "Hello World", except instead of printing text, you're commanding a GPU to draw coloured pixels. Riveting stuff.

## What We're Building

A single triangle rendered with Metal (Apple's graphics API). It'll have three vertices, three colours (red, green, blue), and will sit there looking smug because it exists entirely on the GPU.

The finished app displays a gradient-filled triangle. No buttons, no interaction, just pure rendering. If you can draw a triangle, you can draw anything - it's just more triangles.

## Python Parallel: matplotlib vs GPU Rendering

In Python, you might do this:
```python
import matplotlib.pyplot as plt
import numpy as np

triangle = np.array([[0, 0.5], [-0.5, -0.5], [0.5, -0.5]])
plt.fill(triangle[:, 0], triangle[:, 1])
plt.show()
```

That's CPU-based, matplotlib handles the rendering, and you're trusting layers of abstraction. With Metal, you're talking directly to the GPU. More verbose, but you get microsecond frame times and complete control.

### Architecture Decision

We're using SwiftUI for the UI scaffolding but dropping down to UIKit (via `UIViewRepresentable`) for Metal. Why? Because SwiftUI doesn't have native Metal support yet. Classic Apple.

The `Renderer` class owns all Metal objects and handles drawing. It's our equivalent of a Python graphics context, except we're managing GPU memory ourselves.

## Core Concepts

### Metal Pipeline

```
CPU (Swift) → Command Buffer → Command Encoder → GPU → Drawable → Screen
```

1. **Device**: Your GPU. Singleton object representing hardware.
2. **Command Queue**: FIFO queue of GPU commands. Persistent.
3. **Command Buffer**: Single frame's worth of commands. Transient.
4. **Render Pass**: One drawing operation (clear screen, draw stuff).
5. **Pipeline State**: GPU program configuration (shaders, vertex layout).

### Vertex Data

Unlike Python where you'd use NumPy arrays, we're defining a C-style struct:

```swift
struct Vertex {
    var position: SIMD3<Float>  // x, y, z
    var color: SIMD4<Float>     // r, g, b, a
}
```

`SIMD3` and `SIMD4` are Swift's vector types. They map directly to GPU registers. Python doesn't have native SIMD types; you'd use NumPy's arrays and hope the compiler vectorises things.

### Shaders

GPU code written in Metal Shading Language (MSL), which is C++14-based. These run on the GPU:

- **Vertex Shader**: Transforms vertex positions (3D → 2D projection)
- **Fragment Shader**: Colours pixels (rasterisation)

### Step 4: Metal View Wrapper

`MetalView.swift`:
```swift
import SwiftUI
import MetalKit

struct MetalView: UIViewRepresentable {
    func makeCoordinator() -> Renderer {
        Renderer(metalView: MTKView())
    }

    func makeUIView(context: Context) -> MTKView {
        let metalView = MTKView()
        metalView.device = MTLCreateSystemDefaultDevice()
        metalView.delegate = context.coordinator
        metalView.clearColor = MTLClearColor(red: 0.1, green: 0.1, blue: 0.1, alpha: 1.0)
        metalView.colorPixelFormat = .bgra8Unorm

        context.coordinator.metalView = metalView

        return metalView
    }

    func updateUIView(_ uiView: MTKView, context: Context) {
        // Nothing to update
    }
}
```

**Breakdown**:
- `UIViewRepresentable`: SwiftUI's bridge to UIKit. Like embedding a Tkinter widget in a Qt app. Awkward but necessary.
- `MTKView`: Metal rendering view. It's a `UIView` subclass that provides a drawable surface.
- `makeCoordinator()`: Creates our renderer. SwiftUI's way of attaching data to views.
- `makeUIView()`: Sets up the Metal device and assigns our renderer as delegate.
- Clear colour is dark grey because black backgrounds are for cowards.

### Step 5: The Renderer

`Renderer.swift`:
```swift
import MetalKit

class Renderer: NSObject, MTKViewDelegate {
    var device: MTLDevice!
    var commandQueue: MTLCommandQueue!
    var pipelineState: MTLRenderPipelineState!
    var vertexBuffer: MTLBuffer!
    weak var metalView: MTKView?

    init(metalView: MTKView) {
        super.init()
        self.metalView = metalView
        setupMetal()
        createVertexBuffer()
        createPipeline()
    }

    func setupMetal() {
        device = MTLCreateSystemDefaultDevice()
        commandQueue = device.makeCommandQueue()
    }

    func createVertexBuffer() {
        // Define triangle vertices
        let vertices: [Vertex] = [
            Vertex(position: SIMD3<Float>(0.0, 0.5, 0.0),   // Top - Red
                   color: SIMD4<Float>(1.0, 0.0, 0.0, 1.0)),
            Vertex(position: SIMD3<Float>(-0.5, -0.5, 0.0), // Bottom-left - Green
                   color: SIMD4<Float>(0.0, 1.0, 0.0, 1.0)),
            Vertex(position: SIMD3<Float>(0.5, -0.5, 0.0),  // Bottom-right - Blue
                   color: SIMD4<Float>(0.0, 0.0, 1.0, 1.0))
        ]

        let size = vertices.count * MemoryLayout<Vertex>.stride
        vertexBuffer = device.makeBuffer(bytes: vertices, length: size, options: [])
    }

    func createPipeline() {
        let library = device.makeDefaultLibrary()
        let vertexFunction = library?.makeFunction(name: "vertex_main")
        let fragmentFunction = library?.makeFunction(name: "fragment_main")

        let pipelineDescriptor = MTLRenderPipelineDescriptor()
        pipelineDescriptor.vertexFunction = vertexFunction
        pipelineDescriptor.fragmentFunction = fragmentFunction
        pipelineDescriptor.colorAttachments[0].pixelFormat = .bgra8Unorm

        pipelineState = try! device.makeRenderPipelineState(descriptor: pipelineDescriptor)
    }

    // MARK: - MTKViewDelegate

    func mtkView(_ view: MTKView, drawableSizeWillChange size: CGSize) {
        // Handle resize if needed
    }

    func draw(in view: MTKView) {
        guard let drawable = view.currentDrawable,
              let descriptor = view.currentRenderPassDescriptor else { return }

        let commandBuffer = commandQueue.makeCommandBuffer()!
        let renderEncoder = commandBuffer.makeRenderCommandEncoder(descriptor: descriptor)!

        renderEncoder.setRenderPipelineState(pipelineState)
        renderEncoder.setVertexBuffer(vertexBuffer, offset: 0, index: 0)
        renderEncoder.drawPrimitives(type: .triangle, vertexStart: 0, vertexCount: 3)
        renderEncoder.endEncoding()

        commandBuffer.present(drawable)
        commandBuffer.commit()
    }
}

struct Vertex {
    var position: SIMD3<Float>
    var color: SIMD4<Float>
}
```

**Key Points**:

1. **setupMetal()**: Gets GPU device and creates command queue. The queue is persistent and thread-safe.

2. **createVertexBuffer()**: Allocates GPU memory and copies vertex data. `MemoryLayout<Vertex>.stride` is Swift's way of getting struct size (like Python's `sys.getsizeof()` but accurate).

3. **createPipeline()**: Loads shader functions and configures GPU pipeline. The `try!` is force-unwrapping; we crash if this fails because there's no recovery anyway.

4. **draw()**: Called every frame (60fps). This is your render loop.
   - Get drawable surface (the actual screen framebuffer)
   - Create command buffer (per-frame GPU commands)
   - Create render encoder (records drawing commands)
   - Set pipeline and vertex buffer
   - Issue draw call
   - Present to screen

The Python equivalent would be something like:
```python
def draw(self):
    with self.gpu_context() as ctx:
        ctx.set_pipeline(self.pipeline)
        ctx.set_buffer(self.vertices)
        ctx.draw(primitive='triangles', count=3)
        ctx.present()
```

Except Python doesn't have this because you'd use Pygame or ModernGL, which hide these details.

### Step 6: The Shaders

`Shaders.metal`:
```metal
#include <metal_stdlib>
using namespace metal;

struct Vertex {
    float3 position [[attribute(0)]];
    float4 color [[attribute(1)]];
};

struct RasterizerData {
    float4 position [[position]];
    float4 color;
};

vertex RasterizerData vertex_main(Vertex in [[stage_in]]) {
    RasterizerData out;
    out.position = float4(in.position, 1.0);
    out.color = in.color;
    return out;
}

fragment float4 fragment_main(RasterizerData in [[stage_in]]) {
    return in.color;
}
```

**Shader Breakdown**:

- **Vertex Shader** (`vertex_main`):
  - Takes `Vertex` struct (our CPU-side data)
  - Returns `RasterizerData` (GPU-side data for rasterisation)
  - Converts 3D position to 4D homogeneous coordinates (the `1.0` is the w component)
  - Passes colour through unchanged

- **Fragment Shader** (`fragment_main`):
  - Takes interpolated `RasterizerData` (GPU automatically interpolates between vertices)
  - Returns final pixel colour
  - Just returns the interpolated colour. Hence the gradient effect.

The `[[attribute(0)]]` syntax is Metal's way of binding struct members to vertex attributes. In OpenGL, you'd use `glVertexAttribPointer()`. In Vulkan, you'd write 50 lines of descriptor set bindings. Metal keeps it concise.

## Build and Run

Hit Cmd+R in Xcode. You should see a triangle with a red top vertex, green bottom-left, and blue bottom-right. The colours blend in between because of fragment shader interpolation.

If you see a black screen:
1. Check the debug console for Metal validation errors
2. Verify your device supports Metal (it should, unless you're on a 2011 MacBook)
3. Check the clear colour isn't black
4. Add breakpoints in `draw()` to verify it's being called

## Common Pitfalls

### 1. Memory Management
Metal buffers live on the GPU. When you create one with `makeBuffer()`, it copies data immediately. Changing your CPU-side `vertices` array later does nothing. You'd need to either:
- Recreate the buffer
- Map the buffer and update it
- Use a shared storage mode

Python programmers: think of this like NumPy arrays backed by CUDA memory. They're separate address spaces.

### 2. Coordinate System
Metal uses normalized device coordinates (NDC):
- x: -1 (left) to +1 (right)
- y: -1 (bottom) to +1 (top)
- z: 0 (near) to +1 (far)

Unlike UIKit where (0,0) is top-left with points, or Python's matplotlib where you define your own axes. If your triangle doesn't appear, check your coordinates are in [-1, 1] range.

### 3. Force Unwrapping
All those `!` operators (`commandBuffer!`, `renderEncoder!`) are force unwraps. In production code, you'd handle these properly with `guard` or `if let`. For a tutorial, crashing immediately is more useful than silent failure.

Python equivalent:
```python
# Bad
value = might_be_none()
value.do_thing()  # AttributeError if None

# Good
value = might_be_none()
if value is not None:
    value.do_thing()
```

### 4. Shader Compilation
Shaders compile at runtime. If there's a syntax error, the app builds fine in Xcode but crashes when creating the pipeline state. Check the console output for Metal shader compilation errors.

## Performance Notes

This triangle renders in ~0.1ms on an A15 chip. That's 10,000 triangles per frame at 60fps before you'd notice. Python's matplotlib would take ~16ms for a single triangle (entire frame budget).

The command buffer approach means the CPU and GPU work in parallel. While the GPU renders frame N, the CPU prepares frame N+1. This pipelining is why modern graphics are so fast.
