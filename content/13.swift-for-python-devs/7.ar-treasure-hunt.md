# Tutorial 7: AR Treasure Hunt

Build an augmented reality game where virtual objects exist in physical space. This is where iOS leaves Python in the dust.

## What We're Building

An AR scavenger hunt game:
- Camera feed shows the real world
- Virtual treasures (glowing cubes) spawn at random locations
- Plane detection finds floors/tables to place objects on
- Tap treasures to collect them (they disappear with particle effect)
- Score tracking and win condition
- Distance indicators (how far away treasures are)
- Works indoors and outdoors

Think Pokémon Go but simpler and you actually understand how it works.

## Python Parallel: AR Libraries

Python has AR frameworks (OpenCV + ArUco markers, MediaPipe), but nothing like ARKit's integration:

```python
# Python: marker-based AR
import cv2
import cv2.aruco as aruco

detector = aruco.ArucoDetector(dictionary)
corners, ids = detector.detectMarkers(frame)
# ... manually compute pose, project 3D points
```

This works for marker-based AR (print a QR code, track it). ARKit does **markerless** AR:
- Visual-inertial odometry (camera + IMU fusion)
- SLAM (simultaneous localization and mapping)
- Plane detection (finds flat surfaces automatically)
- Light estimation (matches virtual lighting to real world)
- Hardware-accelerated ML models for depth estimation

You're not building this from scratch. Apple spent years on it. You just use the API.

## Core Concepts

### ARKit Architecture

```
ARSession → ARFrame → Camera Transform + Anchors + Feature Points
    ↓
ARView → RealityKit → Renders AR scene
    ↓
Screen → Composited AR + real camera feed
```

1. **ARSession**: Manages device tracking (position/orientation in world)
2. **ARFrame**: Single frame of data (camera image, transform, detected planes)
3. **ARAnchor**: Fixed position in real world (persists across frames)
4. **ARView**: Displays camera feed + virtual content

### Coordinate Systems

- **World Space**: ARKit's persistent coordinate system (origin at app start location)
- **Camera Space**: Relative to device camera
- **Local Space**: Relative to each virtual object (anchors)

When you place an object at (1, 0, -2) in world space, it stays there even as you walk around. The camera moves, not the object.

### Plane Detection

ARKit analyzes camera frames to detect flat surfaces (horizontal/vertical). When detected:
```swift
func session(_ session: ARSession, didAdd anchors: [ARAnchor]) {
    for anchor in anchors {
        if let planeAnchor = anchor as? ARPlaneAnchor {
            // Plane detected at planeAnchor.transform
        }
    }
}
```

You can visualize planes (helpful for debugging) or just use them for object placement.

### Hit Testing

Converting 2D screen tap → 3D world position:
```swift
let results = arView.raycast(from: screenPoint, allowing: .estimatedPlane, alignment: .horizontal)
if let firstResult = results.first {
    // Place object at firstResult.worldTransform
}
```

This shoots a ray from screen point into 3D space and finds intersections with detected planes.

### Step 2: Game State

`Game/GameState.swift`:
```swift
import Foundation
import Combine

class GameState: ObservableObject {
    @Published var score: Int = 0
    @Published var treasuresRemaining: Int = 5
    @Published var isGameOver: Bool = false

    func collectTreasure() {
        score += 100
        treasuresRemaining -= 1

        if treasuresRemaining == 0 {
            isGameOver = true
        }
    }

    func reset() {
        score = 0
        treasuresRemaining = 5
        isGameOver = false
    }
}
```

Simple state tracking. In a real game, you'd add:
- Treasure types with different values
- Time limits
- Power-ups
- Leaderboards

### Step 3: Treasure Entity

`Game/Treasure.swift`:
```swift
import RealityKit

class Treasure {
    var entity: ModelEntity
    var id: UUID

    init(position: SIMD3<Float>) {
        self.id = UUID()

        // Create glowing cube
        let mesh = MeshResource.generateBox(size: 0.1)
        var material = SimpleMaterial()
        material.color = .init(tint: .yellow, texture: nil)
        material.metallic = .init(floatLiteral: 0.8)
        material.roughness = .init(floatLiteral: 0.2)

        entity = ModelEntity(mesh: mesh, materials: [material])
        entity.position = position

        // Add glow animation
        entity.components.set(OpacityComponent(opacity: 1.0))

        // Rotate continuously
        let rotation = Transform(pitch: 0, yaw: .pi * 2, roll: 0)
        entity.move(to: rotation, relativeTo: entity, duration: 2.0, timingFunction: .linear)
    }

    func distanceFrom(camera: SIMD3<Float>) -> Float {
        return distance(entity.position, camera)
    }
}
```

**RealityKit Notes**:
- **ModelEntity**: Renderable 3D object (mesh + materials)
- **SimpleMaterial**: PBR material (physically-based rendering). Metallic + roughness control appearance.
- **Animation**: `move(to:)` creates a rotation animation. RealityKit handles interpolation.

Python doesn't have an equivalent - you'd manually implement entity systems, animation, and rendering.

### Step 4: AR Coordinator

`AR/ARCoordinator.swift`:
```swift
import ARKit
import RealityKit
import Combine

class ARCoordinator: NSObject, ARSessionDelegate {
    var arView: ARView
    var gameState: GameState

    var treasures: [UUID: Treasure] = [:]
    var planesDetected: Set<UUID> = []

    init(arView: ARView, gameState: GameState) {
        self.arView = arView
        self.gameState = gameState
        super.init()

        setupARSession()
        spawnTreasures()
    }

    func setupARSession() {
        let configuration = ARWorldTrackingConfiguration()
        configuration.planeDetection = [.horizontal]
        configuration.environmentTexturing = .automatic

        arView.session.delegate = self
        arView.session.run(configuration)

        // Enable debug options (remove in production)
        #if DEBUG
        arView.debugOptions = [.showFeaturePoints, .showAnchorOrigins]
        #endif
    }

    func spawnTreasures() {
        // Spawn treasures at random positions around the user
        for _ in 0..<gameState.treasuresRemaining {
            let angle = Float.random(in: 0..<2 * .pi)
            let distance = Float.random(in: 1.0...3.0)

            let x = sin(angle) * distance
            let z = cos(angle) * distance
            let y = Float.random(in: 0.2...1.0)  // Height above ground

            let position = SIMD3<Float>(x, y, z)
            let treasure = Treasure(position: position)

            // Create anchor to persist position
            let anchor = AnchorEntity(world: position)
            anchor.addChild(treasure.entity)
            arView.scene.addAnchor(anchor)

            treasures[treasure.id] = treasure
        }
    }

    func handleTap(at location: CGPoint) {
        // Raycast from screen point into 3D space
        let results = arView.hitTest(location)

        for result in results {
            // Check if we hit a treasure entity
            for (id, treasure) in treasures {
                if result.entity == treasure.entity {
                    collectTreasure(id: id)
                    return
                }
            }
        }
    }

    func collectTreasure(id: UUID) {
        guard let treasure = treasures[id] else { return }

        // Remove from scene
        treasure.entity.removeFromParent()
        treasures.removeValue(forKey: id)

        // Update game state
        gameState.collectTreasure()

        // Spawn particle effect (simple flash)
        // In production, use RealityKit particle systems
    }

    // MARK: - ARSessionDelegate

    func session(_ session: ARSession, didAdd anchors: [ARAnchor]) {
        for anchor in anchors {
            if let planeAnchor = anchor as? ARPlaneAnchor {
                planesDetected.insert(planeAnchor.identifier)
                print("Plane detected: \(planeAnchor.extent.x)m × \(planeAnchor.extent.z)m")
            }
        }
    }

    func session(_ session: ARSession, didUpdate frame: ARFrame) {
        // Called every frame - use for continuous checks

        // Example: update treasure distance indicators
        let cameraPos = frame.camera.transform.translation

        for (_, treasure) in treasures {
            let dist = treasure.distanceFrom(camera: cameraPos)
            // Could update UI with distance: "Treasure 5.2m away"
        }
    }
}

extension simd_float4x4 {
    var translation: SIMD3<Float> {
        return SIMD3(columns.3.x, columns.3.y, columns.3.z)
    }
}
```

**Key Points**:

1. **ARWorldTrackingConfiguration**: Full 6DOF tracking (position + orientation). Alternative: AROrientationTrackingConfiguration (orientation only, like Cardboard VR).

2. **Plane Detection**: `.horizontal` finds floors/tables. `.vertical` finds walls. Both = `.horizontal, .vertical`.

3. **AnchorEntity**: Attaches virtual objects to real-world positions. Anchors persist even when objects leave camera view.

4. **Hit Testing**: `arView.hitTest()` finds entities under screen point. Alternative: `arView.raycast()` for plane intersections.

5. **Debug Options**: `.showFeaturePoints` shows yellow dots (visual features ARKit tracks). Useful for understanding how tracking works.

### Step 5: ARView Container

`AR/ARViewContainer.swift`:
```swift
import SwiftUI
import ARKit
import RealityKit

struct ARViewContainer: UIViewRepresentable {
    @ObservedObject var gameState: GameState

    func makeUIView(context: Context) -> ARView {
        let arView = ARView(frame: .zero)

        context.coordinator.arView = arView
        context.coordinator.gameState = gameState
        context.coordinator.setupARSession()
        context.coordinator.spawnTreasures()

        // Add tap gesture
        let tapGesture = UITapGestureRecognizer(
            target: context.coordinator,
            action: #selector(ARCoordinator.handleTapGesture(_:))
        )
        arView.addGestureRecognizer(tapGesture)

        return arView
    }

    func updateUIView(_ uiView: ARView, context: Context) {
        // Handle state changes if needed
    }

    func makeCoordinator() -> ARCoordinator {
        ARCoordinator(arView: ARView(), gameState: gameState)
    }
}

extension ARCoordinator {
    @objc func handleTapGesture(_ recognizer: UITapGestureRecognizer) {
        let location = recognizer.location(in: arView)
        handleTap(at: location)
    }
}
```

Standard UIViewRepresentable wrapper. ARView isn't a SwiftUI view, so we bridge it.

## Build and Run

**Important**: ARKit only works on physical devices (iPhone 6S+). The simulator doesn't have AR support.

1. Connect your iPhone
2. Select it as run destination
3. Cmd+R
4. Grant camera permission
5. Move phone around slowly to initialize tracking
6. Yellow cubes appear around you
7. Tap them to collect

Tips for testing:
- Start in a well-lit room
- Move slowly (ARKit needs time to track features)
- Point at textured surfaces (blank walls are hard to track)
- If tracking fails, restart the app

## Common Pitfalls

### 1. Tracking Failure

ARKit loses tracking if:
- Too dark (needs visible features)
- Too bright (camera exposure maxed out)
- Moving too fast (motion blur)
- Pointing at featureless surfaces (blank walls, ceilings)

Solution: Show UI warning when `frame.camera.trackingState != .normal`:
```swift
if case .limited(let reason) = frame.camera.trackingState {
    // Show "Point at textured surface" message
}
```

### 2. Scale Confusion

ARKit uses meters. If your treasures are gigantic or invisible:
```swift
let mesh = MeshResource.generateBox(size: 100)  // 100 meters!!! Wrong
let mesh = MeshResource.generateBox(size: 0.1)  // 10cm, correct
```

Common mistake coming from other graphics APIs that use arbitrary units.

### 3. Coordinate System Mismatch

ARKit's Y-axis points up (like real world). Some 3D modeling tools use Z-up. If your objects are sideways, rotate them:
```swift
entity.transform.rotation = simd_quatf(angle: .pi/2, axis: [1, 0, 0])
```

### 4. Memory Leaks with Anchors

Anchors persist until explicitly removed. If you spawn objects continuously without cleanup, you'll run out of memory. Always remove old anchors:
```swift
treasure.entity.removeFromParent()
```

### 5. Battery Drain

AR uses camera, GPU, ML models continuously. Battery drains in ~90 minutes. For longer sessions:
- Lower frame rate: `configuration.frameSemantics = .lowResolution`
- Disable unused features: `configuration.planeDetection = []`
- Pause tracking when app backgrounded

## Performance Notes

ARKit runs at 60fps on modern devices (iPhone 12+). Breakdown:
- Camera capture: ~5ms
- Visual tracking: ~8ms
- RealityKit rendering: ~4ms
- Your game logic: <1ms
- Total: ~18ms per frame (11ms headroom)

With 50 treasures, rendering still hits 60fps. With 1000, you'd need:
- Frustum culling (only render visible objects)
- LOD (simpler models for distant objects)
- Instanced rendering

Our simple approach works for <100 objects.

## Real-World Applications

Beyond games, this technique enables:
- **Interior Design**: Place virtual furniture in rooms
- **Education**: Overlay anatomy models on physical space
- **Navigation**: AR arrows showing directions
- **Industrial**: Maintenance instructions overlaid on machinery
- **Art**: Installations that combine physical and virtual elements

ARKit is powerful, but remember: users must hold their phone up continuously. For >2 minutes, it's fatiguing. Design accordingly.
