# Tutorial 2: Spinning Cube

Now we add a third dimension and make things move. This is where you learn why graphics programmers care so much about linear algebra.

## What We're Building

A 3D cube that spins continuously on screen. Each face is a different colour. You'll implement:
- 3D vertex positions and transformation matrices
- Perspective projection (making distant things smaller)
- Animation via uniform buffers
- Depth testing (so back faces don't draw over front faces)
- Basic camera positioning

The cube rotates on all three axes simultaneously because subtlety is for the weak.

## Python Parallel: 3D Transformations

In Python with NumPy, you might do:
```python
import numpy as np

def rotation_matrix(angle, axis):
    # Rodrigues' rotation formula
    c, s = np.cos(angle), np.sin(angle)
    # ... 20 lines of matrix maths
    return matrix

vertices_3d = np.array([[x, y, z], ...])
rotated = vertices_3d @ rotation_matrix(angle, axis)
projected = perspective_project(rotated, fov, aspect)
```

With Metal, you're doing the same maths but the GPU executes it in parallel for all vertices. Instead of NumPy's `@` operator, you use SIMD matrix multiplication in shaders.

## Core Concepts

### 3D Transformation Pipeline

```
Model Space → World Space → View Space → Clip Space → Screen Space
     |             |             |            |            |
  (Model)      (View)      (Projection)  (Perspective  (Viewport)
                                          Division)
```

1. **Model Matrix**: Positions/rotates/scales the object itself
2. **View Matrix**: Camera position and orientation
3. **Projection Matrix**: Perspective or orthographic mapping
4. **MVP Matrix**: Combined transformation (Model × View × Projection)

Python folks: this is like transforming coordinates through multiple reference frames. If you've done coordinate transformations in pandas or spatial data, same concept but in 3D.

### Uniform Buffers

In the triangle tutorial, vertices were static. Now we need to pass per-frame data (rotation angle, time) to shaders. That's what uniforms are for:

```swift
struct Uniforms {
    var modelViewProjectionMatrix: float4x4
}
```

Every frame, we update this buffer and send it to the GPU. The vertex shader reads it and transforms vertices accordingly.

### Depth Testing

Without depth testing, triangles draw in submission order. Triangle submitted last draws on top, even if it's behind another triangle in 3D space. Depth testing uses a depth buffer (z-buffer) to track pixel depth and only draw pixels that are closer to the camera.

### Step 2: Transform Utilities

`Transforms.swift`:
```swift
import simd

extension float4x4 {
    init(perspectiveProjectionFov fov: Float, aspectRatio aspect: Float, nearZ: Float, farZ: Float) {
        let yScale = 1 / tan(fov * 0.5)
        let xScale = yScale / aspect
        let zRange = farZ - nearZ
        let zScale = -(farZ + nearZ) / zRange
        let wzScale = -2 * farZ * nearZ / zRange

        let P = float4(xScale, 0, 0, 0)
        let Q = float4(0, yScale, 0, 0)
        let R = float4(0, 0, zScale, -1)
        let S = float4(0, 0, wzScale, 0)

        self.init(P, Q, R, S)
    }

    init(translationX x: Float, y: Float, z: Float) {
        self.init(float4(1, 0, 0, 0),
                  float4(0, 1, 0, 0),
                  float4(0, 0, 1, 0),
                  float4(x, y, z, 1))
    }

    init(rotationAngle angle: Float, x: Float, y: Float, z: Float) {
        let c = cos(angle)
        let s = sin(angle)

        let axis = normalize(float3(x, y, z))
        let t = 1 - c

        let X = float4(
            t * axis.x * axis.x + c,
            t * axis.x * axis.y + s * axis.z,
            t * axis.x * axis.z - s * axis.y,
            0
        )

        let Y = float4(
            t * axis.x * axis.y - s * axis.z,
            t * axis.y * axis.y + c,
            t * axis.y * axis.z + s * axis.x,
            0
        )

        let Z = float4(
            t * axis.x * axis.z + s * axis.y,
            t * axis.y * axis.z - s * axis.x,
            t * axis.z * axis.z + c,
            0
        )

        let W = float4(0, 0, 0, 1)

        self.init(X, Y, Z, W)
    }

    init(scaleX x: Float, y: Float, z: Float) {
        self.init(float4(x, 0, 0, 0),
                  float4(0, y, 0, 0),
                  float4(0, 0, z, 0),
                  float4(0, 0, 0, 1))
    }
}

func radians(fromDegrees degrees: Float) -> Float {
    return degrees * .pi / 180
}
```

**Notes**:
- `float4x4` is a 4×4 matrix type from the simd library
- Perspective projection uses field-of-view (FOV) to determine how much perspective distortion
- Rotation matrix uses Rodrigues' rotation formula (same as the NumPy example)
- These are extension methods, so you can do `float4x4(rotationAngle: .pi, x: 0, y: 1, z: 0)`

In Python, you'd probably use `scipy.spatial.transform.Rotation` or roll your own with NumPy. Same maths, different syntax.

### Step 3: Renderer with 3D Support

`Renderer.swift`:
```swift
import MetalKit

class Renderer: NSObject, MTKViewDelegate {
    var device: MTLDevice!
    var commandQueue: MTLCommandQueue!
    var pipelineState: MTLRenderPipelineState!
    var depthStencilState: MTLDepthStencilState!
    var vertexBuffer: MTLBuffer!
    var indexBuffer: MTLBuffer!
    var uniformBuffer: MTLBuffer!
    weak var metalView: MTKView?

    var rotation: Float = 0
    var lastUpdateTime: CFTimeInterval = CACurrentMediaTime()

    init(metalView: MTKView) {
        super.init()
        self.metalView = metalView
        setupMetal()
        createBuffers()
        createPipeline()
        createDepthStencilState()
    }

    func setupMetal() {
        device = MTLCreateSystemDefaultDevice()
        commandQueue = device.makeCommandQueue()
    }

    func createBuffers() {
        // Cube vertices: 8 corners, each with position and color
        let vertices: [Vertex] = [
            // Front face (red-ish)
            Vertex(position: SIMD3<Float>(-1, -1,  1), color: SIMD4<Float>(1.0, 0.0, 0.0, 1.0)),
            Vertex(position: SIMD3<Float>( 1, -1,  1), color: SIMD4<Float>(1.0, 0.3, 0.0, 1.0)),
            Vertex(position: SIMD3<Float>( 1,  1,  1), color: SIMD4<Float>(1.0, 0.6, 0.0, 1.0)),
            Vertex(position: SIMD3<Float>(-1,  1,  1), color: SIMD4<Float>(1.0, 0.9, 0.0, 1.0)),

            // Back face (blue-ish)
            Vertex(position: SIMD3<Float>(-1, -1, -1), color: SIMD4<Float>(0.0, 0.0, 1.0, 1.0)),
            Vertex(position: SIMD3<Float>( 1, -1, -1), color: SIMD4<Float>(0.0, 0.3, 1.0, 1.0)),
            Vertex(position: SIMD3<Float>( 1,  1, -1), color: SIMD4<Float>(0.0, 0.6, 1.0, 1.0)),
            Vertex(position: SIMD3<Float>(-1,  1, -1), color: SIMD4<Float>(0.0, 0.9, 1.0, 1.0))
        ]

        // Indices for cube faces (2 triangles per face, 6 faces)
        let indices: [UInt16] = [
            // Front
            0, 1, 2,  2, 3, 0,
            // Back
            5, 4, 7,  7, 6, 5,
            // Left
            4, 0, 3,  3, 7, 4,
            // Right
            1, 5, 6,  6, 2, 1,
            // Top
            3, 2, 6,  6, 7, 3,
            // Bottom
            4, 5, 1,  1, 0, 4
        ]

        let vertexSize = vertices.count * MemoryLayout<Vertex>.stride
        vertexBuffer = device.makeBuffer(bytes: vertices, length: vertexSize, options: [])

        let indexSize = indices.count * MemoryLayout<UInt16>.stride
        indexBuffer = device.makeBuffer(bytes: indices, length: indexSize, options: [])

        uniformBuffer = device.makeBuffer(length: MemoryLayout<Uniforms>.stride, options: [])
    }

    func createPipeline() {
        let library = device.makeDefaultLibrary()
        let vertexFunction = library?.makeFunction(name: "vertex_main")
        let fragmentFunction = library?.makeFunction(name: "fragment_main")

        let pipelineDescriptor = MTLRenderPipelineDescriptor()
        pipelineDescriptor.vertexFunction = vertexFunction
        pipelineDescriptor.fragmentFunction = fragmentFunction
        pipelineDescriptor.colorAttachments[0].pixelFormat = .bgra8Unorm
        pipelineDescriptor.depthAttachmentPixelFormat = .depth32Float

        pipelineState = try! device.makeRenderPipelineState(descriptor: pipelineDescriptor)
    }

    func createDepthStencilState() {
        let depthDescriptor = MTLDepthStencilDescriptor()
        depthDescriptor.depthCompareFunction = .less
        depthDescriptor.isDepthWriteEnabled = true
        depthStencilState = device.makeDepthStencilState(descriptor: depthDescriptor)
    }

    func updateUniforms() {
        let currentTime = CACurrentMediaTime()
        let deltaTime = Float(currentTime - lastUpdateTime)
        lastUpdateTime = currentTime

        rotation += deltaTime * 1.0  // Rotate 1 radian per second

        // Model matrix: rotation on all axes
        let modelMatrix = float4x4(rotationAngle: rotation, x: 1, y: 1, z: 1)

        // View matrix: camera back 5 units
        let viewMatrix = float4x4(translationX: 0, y: 0, z: -5)

        // Projection matrix
        guard let view = metalView else { return }
        let aspect = Float(view.bounds.width / view.bounds.height)
        let fov = radians(fromDegrees: 65)
        let projectionMatrix = float4x4(perspectiveProjectionFov: fov,
                                        aspectRatio: aspect,
                                        nearZ: 0.1,
                                        farZ: 100)

        // Combine transformations
        var uniforms = Uniforms()
        uniforms.modelViewProjectionMatrix = projectionMatrix * viewMatrix * modelMatrix

        // Copy to GPU buffer
        let bufferPointer = uniformBuffer.contents()
        bufferPointer.copyMemory(from: &uniforms, byteCount: MemoryLayout<Uniforms>.stride)
    }

    // MARK: - MTKViewDelegate

    func mtkView(_ view: MTKView, drawableSizeWillChange size: CGSize) {
        // Projection matrix updates in updateUniforms()
    }

    func draw(in view: MTKView) {
        updateUniforms()

        guard let drawable = view.currentDrawable,
              let descriptor = view.currentRenderPassDescriptor else { return }

        let commandBuffer = commandQueue.makeCommandBuffer()!
        let renderEncoder = commandBuffer.makeRenderCommandEncoder(descriptor: descriptor)!

        renderEncoder.setRenderPipelineState(pipelineState)
        renderEncoder.setDepthStencilState(depthStencilState)
        renderEncoder.setVertexBuffer(vertexBuffer, offset: 0, index: 0)
        renderEncoder.setVertexBuffer(uniformBuffer, offset: 0, index: 1)

        renderEncoder.drawIndexedPrimitives(type: .triangle,
                                           indexCount: 36,  // 12 triangles × 3 indices
                                           indexType: .uint16,
                                           indexBuffer: indexBuffer,
                                           indexBufferOffset: 0)

        renderEncoder.endEncoding()

        commandBuffer.present(drawable)
        commandBuffer.commit()
    }
}

struct Vertex {
    var position: SIMD3<Float>
    var color: SIMD4<Float>
}

struct Uniforms {
    var modelViewProjectionMatrix: float4x4
}
```

**Key Changes from Triangle Tutorial**:

1. **Index Buffer**: Instead of listing vertices 36 times (6 faces × 2 triangles × 3 vertices), we define 8 unique vertices and use indices to reference them. This is more efficient.

2. **Uniform Buffer**: Created with `makeBuffer(length:)` and updated every frame. We're copying data with `copyMemory()` directly into GPU-mapped memory.

3. **Animation**: `updateUniforms()` calculates delta time and increments rotation. This runs every frame before drawing.

4. **Matrix Multiplication**: `projectionMatrix * viewMatrix * modelMatrix` - note the order matters. Matrix multiplication isn't commutative. This transforms vertices from model space → world space → view space → clip space.

5. **Depth State**: `depthCompareFunction = .less` means "only draw if this pixel is closer than what's in the depth buffer".

6. **drawIndexedPrimitives**: Uses index buffer to avoid duplicate vertices.

Python equivalent of the animation loop:
```python
def update(self, dt):
    self.rotation += dt * 1.0
    model = rotation_matrix(self.rotation, axis=[1, 1, 1])
    view = translation_matrix([0, 0, -5])
    proj = perspective_matrix(fov=65, aspect=self.aspect, near=0.1, far=100)
    self.mvp = proj @ view @ model  # NumPy matrix multiplication
```

### Step 4: MetalView with Depth Buffer

`MetalView.swift`:
```swift
import SwiftUI
import MetalKit

struct MetalView: UIViewRepresentable {
    func makeCoordinator() -> Renderer {
        Renderer(metalView: MTKView())
    }

    func makeUIView(context: Context) -> MTKView {
        let metalView = MTKView()
        metalView.device = MTLCreateSystemDefaultDevice()
        metalView.delegate = context.coordinator
        metalView.clearColor = MTLClearColor(red: 0.1, green: 0.1, blue: 0.15, alpha: 1.0)
        metalView.colorPixelFormat = .bgra8Unorm
        metalView.depthStencilPixelFormat = .depth32Float  // NEW: Enable depth buffer
        metalView.preferredFramesPerSecond = 60

        context.coordinator.metalView = metalView

        return metalView
    }

    func updateUIView(_ uiView: MTKView, context: Context) {}
}
```

Only change: added `depthStencilPixelFormat = .depth32Float`. This allocates a depth buffer. Without this, depth testing doesn't work and you get weird rendering artifacts.

### Step 5: Shaders with Transformation

`Shaders.metal`:
```metal
#include <metal_stdlib>
using namespace metal;

struct Vertex {
    float3 position [[attribute(0)]];
    float4 color [[attribute(1)]];
};

struct Uniforms {
    float4x4 modelViewProjectionMatrix;
};

struct RasterizerData {
    float4 position [[position]];
    float4 color;
};

vertex RasterizerData vertex_main(Vertex in [[stage_in]],
                                  constant Uniforms& uniforms [[buffer(1)]]) {
    RasterizerData out;
    out.position = uniforms.modelViewProjectionMatrix * float4(in.position, 1.0);
    out.color = in.color;
    return out;
}

fragment float4 fragment_main(RasterizerData in [[stage_in]]) {
    return in.color;
}
```

**Shader Changes**:

1. **Uniforms Parameter**: `constant Uniforms& uniforms [[buffer(1)]]` - reads from the uniform buffer we bound at index 1
2. **Matrix Transform**: `uniforms.modelViewProjectionMatrix * float4(in.position, 1.0)` applies the full MVP transformation
3. The fragment shader is unchanged

The `constant` address space means this data is read-only and shared across all shader invocations. The GPU can optimise access because it knows the data doesn't change during a draw call.

## Build and Run

Cmd+R. You should see a rotating cube with colour gradients on each face. If the cube looks inside-out or faces flicker, check:

1. **Winding order**: Indices should be counter-clockwise when viewed from outside
2. **Depth test**: Verify depth buffer is enabled in both pipeline and MTKView
3. **Camera distance**: If you're inside the cube (z = -5 isn't enough), move it further back

## Common Pitfalls

### 1. Matrix Multiplication Order

This will bite you. Metal (and most graphics APIs) use column-major matrices. When you do:
```swift
let mvp = projection * view * model
```

It applies transformations right-to-left: first model, then view, then projection. If you reverse the order, everything breaks. Python's NumPy uses row-major by default, so this might feel backwards.

### 2. FOV in Radians

The `perspectiveProjectionFov` function expects radians, not degrees. If you pass 65 directly instead of `radians(fromDegrees: 65)`, you get a FOV of ~3723 degrees. Your cube becomes a single pixel.

### 3. Depth Buffer Precision

We're using `.depth32Float` which is 32-bit floating point. For most scenes this is fine. If you need extreme depth range (e.g., planetary scale to microscopic scale), use `.depth24Unorm_stencil8` or logarithmic depth buffers.

### 4. Uniform Buffer Updates

We're using `copyMemory()` which is simple but not optimal for rapidly changing data. For better performance:
- Use triple-buffering (3 uniform buffers, rotate between them)
- Use shared memory mode for CPU-GPU coherency
- Consider push constants for small amounts of data

Python doesn't have this problem because you're not managing GPU memory directly. But if you've used CUDA or OpenCL, same principles apply.

### 5. Aspect Ratio

We calculate aspect from `view.bounds`. If the view hasn't been laid out yet, you get garbage. Always check the size is non-zero before creating projection matrices.

## Performance Notes

This cube is 8 vertices, 12 triangles, one draw call. Renders in <0.05ms on modern hardware. The bottleneck isn't the cube, it's the uniform buffer update on the CPU.

If you were rendering 10,000 cubes:
- **Bad**: 10,000 draw calls, each with its own uniform buffer
- **Better**: One draw call, instanced rendering, uniforms in a buffer array
- **Best**: Indirect rendering, GPU builds command buffers

We'll cover instancing in the particle system tutorial.
