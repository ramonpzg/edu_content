# Tutorial 2: Spinning Cube

Now we add a third dimension and make things move. This is where you learn why graphics programmers care so much about linear algebra.

## What We're Building

A 3D cube that spins continuously on screen. Each face is a different colour. You'll implement:
- 3D vertex positions and transformation matrices
- Perspective projection (making distant things smaller)
- Animation via uniform updates
- Depth testing (so back faces don't draw over front faces)
- Basic camera positioning

The cube rotates on all three axes simultaneously because subtlety is for the weak.

## Python Parallel: 3D Transformations

In Python with NumPy, you might do:
```python
import numpy as np

def rotation_matrix(angle, axis):
    c, s = np.cos(angle), np.sin(angle)
    # ... 20 lines of matrix maths
    return matrix

vertices_3d = np.array([[x, y, z], ...])
rotated = vertices_3d @ rotation_matrix(angle, axis)
projected = perspective_project(rotated, fov, aspect)
```

With OpenGL ES, you're doing the same maths but the GPU executes it in parallel for all vertices. Instead of NumPy's `@` operator, you use matrix multiplication in shaders.

## Core Concepts

### 3D Transformation Pipeline

```
Model Space → World Space → View Space → Clip Space → Screen Space
     |             |             |            |            |
  (Model)      (View)      (Projection)  (Perspective  (Viewport)
                                          Division)
```

1. **Model Matrix**: Positions/rotates/scales the object itself
2. **View Matrix**: Camera position and orientation
3. **Projection Matrix**: Perspective or orthographic mapping
4. **MVP Matrix**: Combined transformation (Model × View × Projection)

Python folks: this is like transforming coordinates through multiple reference frames. If you've done coordinate transformations in pandas or spatial data, same concept but in 3D.

### Depth Testing

Without depth testing, triangles draw in submission order. Triangle submitted last draws on top, even if it's behind another triangle in 3D space. Depth testing uses a depth buffer (z-buffer) to track pixel depth and only draw pixels that are closer to the camera.

## Implementation

### Step 1: Matrix Utilities

`Matrix.kt`:
```kotlin
package com.example.spinningcube

import android.opengl.Matrix

object MatrixHelper {
    fun perspectiveMatrix(
        fov: Float,
        aspect: Float,
        near: Float,
        far: Float
    ): FloatArray {
        val matrix = FloatArray(16)
        Matrix.perspectiveM(matrix, 0, fov, aspect, near, far)
        return matrix
    }

    fun viewMatrix(
        eyeX: Float, eyeY: Float, eyeZ: Float,
        centerX: Float, centerY: Float, centerZ: Float,
        upX: Float, upY: Float, upZ: Float
    ): FloatArray {
        val matrix = FloatArray(16)
        Matrix.setLookAtM(
            matrix, 0,
            eyeX, eyeY, eyeZ,
            centerX, centerY, centerZ,
            upX, upY, upZ
        )
        return matrix
    }

    fun rotationMatrix(angleX: Float, angleY: Float, angleZ: Float): FloatArray {
        val matrix = FloatArray(16)
        Matrix.setIdentityM(matrix, 0)

        val rotX = FloatArray(16)
        val rotY = FloatArray(16)
        val rotZ = FloatArray(16)

        Matrix.setRotateM(rotX, 0, angleX, 1f, 0f, 0f)
        Matrix.setRotateM(rotY, 0, angleY, 0f, 1f, 0f)
        Matrix.setRotateM(rotZ, 0, angleZ, 0f, 0f, 1f)

        val temp = FloatArray(16)
        Matrix.multiplyMM(temp, 0, rotY, 0, rotX, 0)
        Matrix.multiplyMM(matrix, 0, rotZ, 0, temp, 0)

        return matrix
    }

    fun translateMatrix(x: Float, y: Float, z: Float): FloatArray {
        val matrix = FloatArray(16)
        Matrix.setIdentityM(matrix, 0)
        Matrix.translateM(matrix, 0, x, y, z)
        return matrix
    }
}
```

**Notes**:
- Android provides `android.opengl.Matrix` utility class. Saves you from implementing matrix maths.
- Matrices are `FloatArray(16)` - 4×4 matrices in column-major order.
- `multiplyMM()` multiplies matrices. Order matters: AB ≠ BA for matrices.

### Step 2: Cube Geometry

`Cube.kt`:
```kotlin
package com.example.spinningcube

import android.content.Context
import android.opengl.GLES30
import android.opengl.Matrix
import java.nio.ByteBuffer
import java.nio.ByteOrder
import java.nio.FloatBuffer
import java.nio.ShortBuffer

class Cube(context: Context) {
    private val vertexBuffer: FloatBuffer
    private val indexBuffer: ShortBuffer
    private val program: Int

    private var mvpMatrixHandle: Int = 0
    private val mvpMatrix = FloatArray(16)

    // Cube vertices: 8 corners with positions and colours
    private val vertices = floatArrayOf(
        // Front face (red-ish)
        -1f, -1f,  1f,  1.0f, 0.0f, 0.0f, 1.0f,
         1f, -1f,  1f,  1.0f, 0.3f, 0.0f, 1.0f,
         1f,  1f,  1f,  1.0f, 0.6f, 0.0f, 1.0f,
        -1f,  1f,  1f,  1.0f, 0.9f, 0.0f, 1.0f,

        // Back face (blue-ish)
        -1f, -1f, -1f,  0.0f, 0.0f, 1.0f, 1.0f,
         1f, -1f, -1f,  0.0f, 0.3f, 1.0f, 1.0f,
         1f,  1f, -1f,  0.0f, 0.6f, 1.0f, 1.0f,
        -1f,  1f, -1f,  0.0f, 0.9f, 1.0f, 1.0f
    )

    // Indices for cube faces (2 triangles per face, 6 faces)
    private val indices = shortArrayOf(
        // Front
        0, 1, 2,  2, 3, 0,
        // Back
        5, 4, 7,  7, 6, 5,
        // Left
        4, 0, 3,  3, 7, 4,
        // Right
        1, 5, 6,  6, 2, 1,
        // Top
        3, 2, 6,  6, 7, 3,
        // Bottom
        4, 5, 1,  1, 0, 4
    )

    companion object {
        const val COORDS_PER_VERTEX = 3
        const val COLORS_PER_VERTEX = 4
        const val VERTEX_STRIDE = (COORDS_PER_VERTEX + COLORS_PER_VERTEX) * 4
    }

    init {
        vertexBuffer = ByteBuffer.allocateDirect(vertices.size * 4).run {
            order(ByteOrder.nativeOrder())
            asFloatBuffer().apply {
                put(vertices)
                position(0)
            }
        }

        indexBuffer = ByteBuffer.allocateDirect(indices.size * 2).run {
            order(ByteOrder.nativeOrder())
            asShortBuffer().apply {
                put(indices)
                position(0)
            }
        }

        val vertexShaderCode = """
            #version 300 es
            in vec3 aPosition;
            in vec4 aColor;
            uniform mat4 uMVPMatrix;
            out vec4 vColor;

            void main() {
                gl_Position = uMVPMatrix * vec4(aPosition, 1.0);
                vColor = aColor;
            }
        """.trimIndent()

        val fragmentShaderCode = """
            #version 300 es
            precision mediump float;
            in vec4 vColor;
            out vec4 fragColor;

            void main() {
                fragColor = vColor;
            }
        """.trimIndent()

        val vertexShader = loadShader(GLES30.GL_VERTEX_SHADER, vertexShaderCode)
        val fragmentShader = loadShader(GLES30.GL_FRAGMENT_SHADER, fragmentShaderCode)

        program = GLES30.glCreateProgram().also {
            GLES30.glAttachShader(it, vertexShader)
            GLES30.glAttachShader(it, fragmentShader)
            GLES30.glLinkProgram(it)
        }

        mvpMatrixHandle = GLES30.glGetUniformLocation(program, "uMVPMatrix")
    }

    fun draw(mvpMatrix: FloatArray) {
        GLES30.glUseProgram(program)

        val positionHandle = GLES30.glGetAttribLocation(program, "aPosition")
        val colorHandle = GLES30.glGetAttribLocation(program, "aColor")

        GLES30.glEnableVertexAttribArray(positionHandle)
        GLES30.glEnableVertexAttribArray(colorHandle)

        vertexBuffer.position(0)
        GLES30.glVertexAttribPointer(
            positionHandle, COORDS_PER_VERTEX,
            GLES30.GL_FLOAT, false,
            VERTEX_STRIDE, vertexBuffer
        )

        vertexBuffer.position(COORDS_PER_VERTEX)
        GLES30.glVertexAttribPointer(
            colorHandle, COLORS_PER_VERTEX,
            GLES30.GL_FLOAT, false,
            VERTEX_STRIDE, vertexBuffer
        )

        // Upload MVP matrix to shader
        GLES30.glUniformMatrix4fv(mvpMatrixHandle, 1, false, mvpMatrix, 0)

        // Draw using indices
        GLES30.glDrawElements(
            GLES30.GL_TRIANGLES,
            indices.size,
            GLES30.GL_UNSIGNED_SHORT,
            indexBuffer
        )

        GLES30.glDisableVertexAttribArray(positionHandle)
        GLES30.glDisableVertexAttribArray(colorHandle)
    }

    private fun loadShader(type: Int, shaderCode: String): Int {
        val shader = GLES30.glCreateShader(type)
        GLES30.glShaderSource(shader, shaderCode)
        GLES30.glCompileShader(shader)
        return shader
    }
}
```

**Key Changes**:
- **Index Buffer**: Define 8 unique vertices, reference them with indices. More efficient than 36 separate vertices.
- **Uniform**: `uMVPMatrix` is a uniform (constant across all vertices in a draw call). Updated from CPU each frame.
- **glDrawElements()**: Uses index buffer instead of `glDrawArrays()`.

### Step 3: Renderer with Animation

`CubeRenderer.kt`:
```kotlin
package com.example.spinningcube

import android.content.Context
import android.opengl.GLES30
import android.opengl.GLSurfaceView
import android.opengl.Matrix
import javax.microedition.khronos.egl.EGLConfig
import javax.microedition.khronos.opengles.GL10

class CubeRenderer(private val context: Context) : GLSurfaceView.Renderer {
    private lateinit var cube: Cube

    private val projectionMatrix = FloatArray(16)
    private val viewMatrix = FloatArray(16)
    private val modelMatrix = FloatArray(16)
    private val mvpMatrix = FloatArray(16)

    private var rotation = 0f
    private var lastTime = System.currentTimeMillis()

    override fun onSurfaceCreated(gl: GL10?, config: EGLConfig?) {
        GLES30.glClearColor(0.1f, 0.1f, 0.15f, 1.0f)

        // Enable depth testing
        GLES30.glEnable(GLES30.GL_DEPTH_TEST)
        GLES30.glDepthFunc(GLES30.GL_LESS)

        cube = Cube(context)
    }

    override fun onSurfaceChanged(gl: GL10?, width: Int, height: Int) {
        GLES30.glViewport(0, 0, width, height)

        val aspect = width.toFloat() / height.toFloat()
        Matrix.perspectiveM(projectionMatrix, 0, 65f, aspect, 0.1f, 100f)
    }

    override fun onDrawFrame(gl: GL10?) {
        // Calculate delta time
        val currentTime = System.currentTimeMillis()
        val deltaTime = (currentTime - lastTime) / 1000f
        lastTime = currentTime

        // Update rotation
        rotation += deltaTime * 60f  // 60 degrees per second

        // Clear buffers
        GLES30.glClear(GLES30.GL_COLOR_BUFFER_BIT or GLES30.GL_DEPTH_BUFFER_BIT)

        // Set up view matrix (camera back 5 units)
        Matrix.setLookAtM(
            viewMatrix, 0,
            0f, 0f, 5f,    // Eye position
            0f, 0f, 0f,    // Look at point
            0f, 1f, 0f     // Up vector
        )

        // Set up model matrix (rotation on all axes)
        Matrix.setIdentityM(modelMatrix, 0)
        Matrix.rotateM(modelMatrix, 0, rotation, 1f, 1f, 1f)

        // Combine matrices: MVP = Projection × View × Model
        val temp = FloatArray(16)
        Matrix.multiplyMM(temp, 0, viewMatrix, 0, modelMatrix, 0)
        Matrix.multiplyMM(mvpMatrix, 0, projectionMatrix, 0, temp, 0)

        // Draw cube
        cube.draw(mvpMatrix)
    }
}
```

**Renderer Notes**:
- **Depth Testing**: `glEnable(GL_DEPTH_TEST)` enables z-buffer. `GL_LESS` means closer pixels win.
- **Delta Time**: Calculate time between frames for smooth animation regardless of frame rate.
- **Matrix Multiplication**: Order is critical: `Projection × View × Model`. Reads right-to-left in terms of transformations applied.

Python equivalent:
```python
def update(self, dt):
    self.rotation += dt * 60
    model = rotation_matrix(self.rotation, axis=[1, 1, 1])
    view = lookat(eye=[0, 0, 5], center=[0, 0, 0], up=[0, 1, 0])
    proj = perspective(fov=65, aspect=self.aspect, near=0.1, far=100)
    self.mvp = proj @ view @ model
```

## Build and Run

Run the app. You should see a rotating cube with colour gradients on each face. If the cube looks inside-out or faces flicker, check:

1. **Winding order**: Indices should be counter-clockwise when viewed from outside
2. **Depth test**: Verify depth buffer is enabled
3. **Camera distance**: If you're inside the cube (z = 5 isn't enough), move it further back

## Common Pitfalls

### 1. Matrix Multiplication Order

This will bite you. When you do:
```kotlin
Matrix.multiplyMM(result, 0, matrixA, 0, matrixB, 0)
```

Result = A × B. If you reverse the order, everything breaks. Transformations apply right-to-left. For MVP, you want: `Projection × View × Model`.

### 2. Depth Buffer Not Cleared

```kotlin
// Wrong - depth buffer accumulates from previous frames
GLES30.glClear(GLES30.GL_COLOR_BUFFER_BIT)

// Right - clear both colour and depth
GLES30.glClear(GLES30.GL_COLOR_BUFFER_BIT or GLES30.GL_DEPTH_BUFFER_BIT)
```

Without clearing depth buffer, you get weird artifacts from previous frames.

### 3. GLSurfaceView Config

If depth testing doesn't work, check your GLSurfaceView setup:
```kotlin
glView.setEGLConfigChooser(8, 8, 8, 8, 16, 0)
// R, G, B, A, Depth, Stencil
// 16-bit depth buffer
```

Default config might not allocate a depth buffer.

### 4. Field of View in Degrees

`Matrix.perspectiveM()` expects FOV in degrees, not radians:
```kotlin
// Wrong - FOV in radians (extremely narrow)
Matrix.perspectiveM(matrix, 0, 1.13f, aspect, 0.1f, 100f)

// Right - FOV in degrees
Matrix.perspectiveM(matrix, 0, 65f, aspect, 0.1f, 100f)
```

### 5. Aspect Ratio

Always recalculate aspect in `onSurfaceChanged()`:
```kotlin
override fun onSurfaceChanged(gl: GL10?, width: Int, height: Int) {
    val aspect = width.toFloat() / height.toFloat()
    Matrix.perspectiveM(projectionMatrix, 0, 65f, aspect, 0.1f, 100f)
}
```

If you hardcode aspect ratio, rotating the device squashes/stretches the cube.

## Performance Notes

This cube is 8 vertices, 12 triangles, one draw call. Renders in <0.05ms on modern Android hardware. The bottleneck isn't the cube, it's the matrix multiplication on the CPU.

If you were rendering 10,000 cubes:
- **Bad**: 10,000 draw calls, each with its own matrix
- **Better**: Instanced rendering, matrices in a buffer
- **Best**: Indirect rendering, GPU builds command buffers
