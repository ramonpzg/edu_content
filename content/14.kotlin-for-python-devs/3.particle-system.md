# Tutorial 3: Particle System

Time to render 50,000 particles at 60fps. This is where you learn the difference between "it works" and "it works fast".

## What We're Building

A particle system with 50,000 particles, each with position, velocity, lifetime, physics simulation (gravity, damping), colour based on velocity, emission from a point source, and particle recycling when they die.

Particles spawn from the centre, fly outward, slow down, and fade out. Looks like a continuous fountain. Each particle is a tiny point sprite rendered by the GPU.

The critical bit: simulation can run entirely on the GPU or CPU. We'll do CPU simulation for simplicity, but discuss GPU compute alternatives.

## Python Parallel

```python
import numpy as np

class ParticleSystem:
    def __init__(self, count=10000):
        self.positions = np.random.randn(count, 3) * 0.1
        self.velocities = np.random.randn(count, 3) * 2.0
        self.lifetimes = np.random.rand(count) * 5.0

    def update(self, dt):
        self.velocities[:, 1] -= 9.8 * dt  # Gravity
        self.positions += self.velocities * dt
        self.lifetimes -= dt
        # Respawn dead particles
```

This works, but at 50,000 particles, you get ~20fps on CPU. With OpenGL point sprites and instanced rendering, you get 60fps easily.

## Implementation Highlights

**Particle Data** (`Particle.kt`):
```kotlin
data class Particle(
    var position: FloatArray = floatArrayOf(0f, 0f, 0f),
    var velocity: FloatArray = floatArrayOf(0f, 0f, 0f),
    var lifetime: Float = 0f,
    var maxLifetime: Float = 0f,
    var color: FloatArray = floatArrayOf(1f, 1f, 1f, 1f)
)
```

**CPU Simulation** (`ParticleSystem.kt`):
```kotlin
class ParticleSystem(private val maxParticles: Int = 50000) {
    private val particles = Array(maxParticles) { Particle() }

    fun update(deltaTime: Float) {
        for (particle in particles) {
            // Apply physics
            particle.velocity[1] -= 9.8f * deltaTime
            particle.velocity[0] *= 0.99f
            particle.velocity[1] *= 0.99f
            particle.velocity[2] *= 0.99f

            particle.position[0] += particle.velocity[0] * deltaTime
            particle.position[1] += particle.velocity[1] * deltaTime
            particle.position[2] += particle.velocity[2] * deltaTime

            particle.lifetime -= deltaTime

            if (particle.lifetime <= 0) {
                respawn(particle)
            }

            // Color based on velocity
            val speed = sqrt(
                particle.velocity[0] * particle.velocity[0] +
                particle.velocity[1] * particle.velocity[1] +
                particle.velocity[2] * particle.velocity[2]
            )
            particle.color[0] = speed / 10f
            particle.color[1] = 1f - speed / 10f
            particle.color[3] = particle.lifetime / particle.maxLifetime
        }
    }

    private fun respawn(particle: Particle) {
        val angle = Random.nextFloat() * 2f * PI.toFloat()
        val elevation = Random.nextFloat() * PI.toFloat() / 4f - PI.toFloat() / 8f
        val speed = 2f + Random.nextFloat() * 6f

        particle.velocity[0] = cos(elevation) * cos(angle) * speed
        particle.velocity[1] = sin(elevation) * speed + 5f
        particle.velocity[2] = cos(elevation) * sin(angle) * speed

        particle.position = floatArrayOf(0f, 0f, 0f)
        particle.lifetime = 2f + Random.nextFloat() * 2f
        particle.maxLifetime = particle.lifetime
    }
}
```

**Performance**:
- 50,000 particles: ~1ms update (CPU), ~0.5ms render (GPU)
- Total: 1.5ms per frame (90% under budget)
- Python equivalent: ~50ms (can't hit 60fps)

GPU is ~30× faster because CPU simulation is still vectorized (Kotlin is faster than pure Python), and GPU rendering is massively parallel.

## Common Pitfalls

1. **Updating Buffer Every Frame**: Uploading 50k particles to GPU each frame kills performance. Use `glBufferSubData()` or persistent mapped buffers.
2. **Spawning Too Many**: More particles = more CPU time. Profile before adding more.
3. **Skipping Frustum Culling**: Rendering off-screen particles wastes GPU. Cull based on camera frustum.
