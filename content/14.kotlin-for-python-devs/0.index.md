# Kotlin for Python Developers

A 10-part series teaching Kotlin and Android development from an advanced Python programmer's perspective. No nonsense, no hand-holding, just proper engineering.

## What You'll Build

This isn't one of those "Hello World" affairs that teaches you nothing useful. You'll build 10 progressively complex Android applications:

1. **Hello Triangle** - OpenGL ES graphics fundamentals. Drawing pixels on a GPU.
2. **3D Spinning Cube** - Proper 3D with transforms, cameras, and matrix maths.
3. **Particle System** - Thousands of particles, GPU rendering, performance optimisation.
4. **Snake Game** - Classic game logic with Canvas rendering. Simple but solid.
5. **3D Scene Explorer** - Navigate a textured 3D world with touch gestures.
6. **Data Visualiser** - Parse 100k+ rows, render interactive charts, don't crash.
7. **AR Treasure Hunt** - ARCore game finding objects in physical space.
8. **AI Chatbot** - OpenAI API, Room database persistence, proper coroutines.
9. **Shader Playground** - Write custom GLSL shaders, real-time manipulation.
10. **Multiplayer Sketchpad** - CRDTs for conflict-free collaboration, WebSocket sync.

## Prerequisites

- You already know Python well (decorators, context managers, metaclasses - the lot)
- You're comfortable with systems programming concepts
- You have Android Studio installed and working
- You have a physical Android device or emulator ready

## Kotlin vs Python: The Essentials

Since you're coming from Python, here are the main conceptual shifts:

### Type System
Python: Duck typing, runtime type checks, mypy if you're fancy
Kotlin: Compile-time type checking, nullable types (`String?`), smart casts

### Memory Management
Python: Reference counting + cycle detection, GC for cleanup
Kotlin: JVM garbage collection, no manual memory management (usually)

### Concurrency
Python: GIL-limited threading, asyncio event loop, multiprocessing
Kotlin: Proper threading, coroutines (structured concurrency), Flow (reactive streams)

### Syntax Philosophy
Python: "One obvious way to do it", whitespace matters, explicit over implicit
Kotlin: Multiple paradigms, null safety baked in, functional + OOP, concise but safe

Kotlin feels like a more disciplined Python with static typing. That's not a bug.
