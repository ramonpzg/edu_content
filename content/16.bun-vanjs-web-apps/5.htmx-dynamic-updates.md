# Dynamic Updates with HTMX

Build interactive web apps with HTML attributes instead of JavaScript. Add infinite scroll, live search, form validation, and partial page updates—all with zero client-side code.

## What We're Building

Interactive features using HTMX (v2.0.8):

- Infinite scroll pagination
- Live search (debounced)
- Form validation with server feedback
- Real-time lesson progress updates
- Modal dialogs loaded on-demand
- Optimistic UI updates

**JavaScript bundle reduction**: From 15KB (VanJS app) to 0KB app code + 11KB HTMX library. Total savings: 4KB, plus eliminating duplicate logic between client and server.

## Installation

Include HTMX via CDN:

```html
<!-- client/index.html -->
<script src="https://unpkg.com/htmx.org@2.0.8"></script>
```

Or install locally:

```bash
bun add htmx.org
```

```html
<script src="/static/htmx.min.js"></script>
```

## Basic HTMX Patterns

### Infinite Scroll

**HTML:**
```html
<div id="lesson-list">
  <article class="lesson-card">
    <h2>Lesson 1</h2>
    <p>Introduction to Bun</p>
  </article>

  <article class="lesson-card">
    <h2>Lesson 2</h2>
    <p>VanJS Basics</p>
  </article>

  <!-- Load more trigger -->
  <div hx-get="/api/lessons?offset=2&limit=2"
       hx-trigger="revealed"
       hx-swap="afterend">
    <p>Loading more...</p>
  </div>
</div>
```

**Server endpoint:**
```typescript
// server/index.ts
if (url.pathname === "/api/lessons") {
  const offset = parseInt(url.searchParams.get("offset") || "0");
  const limit = parseInt(url.searchParams.get("limit") || "10");

  const result = await db.execute(
    `SELECT slug, title, description
     FROM lessons
     ORDER BY order_num
     LIMIT ? OFFSET ?`,
    [limit, offset]
  );

  const lessons = result.rows;
  const hasMore = lessons.length === limit;

  // Return HTML fragment
  let html = lessons.map(lesson => `
    <article class="lesson-card">
      <h2><a href="/${lesson.slug}">${lesson.title}</a></h2>
      <p>${lesson.description || ""}</p>
    </article>
  `).join("");

  // Add next page trigger
  if (hasMore) {
    html += `
      <div hx-get="/api/lessons?offset=${offset + limit}&limit=${limit}"
           hx-trigger="revealed"
           hx-swap="afterend">
        <p>Loading more...</p>
      </div>
    `;
  }

  return new Response(html, {
    headers: { "Content-Type": "text/html" },
  });
}
```

**How it works:**

- `hx-get="/api/lessons?offset=2&limit=2"` - URL to fetch
- `hx-trigger="revealed"` - Trigger when element enters viewport
- `hx-swap="afterend"` - Insert response after current element

When user scrolls to "Loading more...", HTMX fetches next page and inserts it. Original trigger element is replaced by response, which includes a new trigger for the next page.

### Live Search (Debounced)

**HTML:**
```html
<input type="search"
       name="q"
       placeholder="Search lessons..."
       hx-get="/api/search"
       hx-trigger="keyup changed delay:300ms"
       hx-target="#search-results">

<div id="search-results"></div>
```

**Server endpoint:**
```typescript
if (url.pathname === "/api/search") {
  const q = url.searchParams.get("q") || "";

  if (q.length < 2) {
    return new Response("<p>Type at least 2 characters</p>", {
      headers: { "Content-Type": "text/html" },
    });
  }

  const result = await db.execute(
    `SELECT slug, title, snippet(lessons_fts, 2, '<mark>', '</mark>', '...', 48) AS snippet
     FROM lessons_fts
     WHERE lessons_fts MATCH ?
     ORDER BY rank
     LIMIT 20`,
    [q]
  );

  if (result.rows.length === 0) {
    return new Response(`<p>No results for "${q}"</p>`, {
      headers: { "Content-Type": "text/html" },
    });
  }

  const html = `
    <ul class="search-results">
      ${result.rows.map(r => `
        <li>
          <a href="/${r.slug}">
            <strong>${r.title}</strong>
            <p>${r.snippet}</p>
          </a>
        </li>
      `).join("")}
    </ul>
  `;

  return new Response(html, {
    headers: { "Content-Type": "text/html" },
  });
}
```

**Trigger breakdown:**

- `keyup` - Fire on any keypress
- `changed` - Only if value actually changed (ignore arrow keys, etc.)
- `delay:300ms` - Wait 300ms after last keypress (debouncing)

This prevents firing a request for every keystroke. User types "bun runtime" → fires one request 300ms after they stop typing.

### Form Validation

**HTML:**
```html
<form hx-post="/api/feedback"
      hx-target="#form-response"
      hx-swap="innerHTML">

  <label>
    Name:
    <input type="text" name="name" required>
  </label>

  <label>
    Email:
    <input type="email" name="email" required>
  </label>

  <label>
    Message:
    <textarea name="message" required></textarea>
  </label>

  <button type="submit">Send Feedback</button>
</form>

<div id="form-response"></div>
```

**Server endpoint:**
```typescript
if (url.pathname === "/api/feedback" && req.method === "POST") {
  const formData = await req.formData();
  const name = formData.get("name") as string;
  const email = formData.get("email") as string;
  const message = formData.get("message") as string;

  // Validation
  const errors: string[] = [];

  if (!name || name.length < 2) {
    errors.push("Name must be at least 2 characters");
  }

  if (!email || !email.includes("@")) {
    errors.push("Valid email required");
  }

  if (!message || message.length < 10) {
    errors.push("Message must be at least 10 characters");
  }

  if (errors.length > 0) {
    return new Response(`
      <div class="error">
        <ul>
          ${errors.map(e => `<li>${e}</li>`).join("")}
        </ul>
      </div>
    `, {
      status: 400,
      headers: { "Content-Type": "text/html" },
    });
  }

  // Save feedback to database
  await db.execute(
    "INSERT INTO feedback (name, email, message, created_at) VALUES (?, ?, ?, ?)",
    [name, email, message, Date.now()]
  );

  return new Response(`
    <div class="success">
      <p>Thank you for your feedback, ${name}!</p>
    </div>
  `, {
    headers: { "Content-Type": "text/html" },
  });
}
```

Form submits via AJAX. Server returns HTML (errors or success message). HTMX replaces `#form-response` content.

**No JavaScript required**. Browser validation happens automatically (`required`, `type="email"`). Server validation provides detailed feedback.

### Progress Tracking

Mark lessons complete with optimistic UI updates:

**HTML:**
```html
<button hx-post="/api/progress/${lessonSlug}/complete"
        hx-swap="outerHTML"
        hx-target="this">
  Mark Complete
</button>
```

**Server endpoint:**
```typescript
if (url.pathname.match(/^\/api\/progress\/(.+)\/complete$/)) {
  const slug = url.pathname.match(/^\/api\/progress\/(.+)\/complete$/)![1];
  const userId = await getUserIdFromSession(req);  // From cookies/JWT

  await db.execute(
    `INSERT INTO user_progress (user_id, lesson_slug, completed, completed_at)
     VALUES (?, ?, TRUE, ?)
     ON CONFLICT (user_id, lesson_slug)
     DO UPDATE SET completed = TRUE, completed_at = ?`,
    [userId, slug, Date.now(), Date.now()]
  );

  // Return updated button state
  return new Response(`
    <button class="completed" disabled>
      ✓ Completed
    </button>
  `, {
    headers: { "Content-Type": "text/html" },
  });
}
```

Click button → HTMX posts to server → server updates database → returns new button HTML → HTMX replaces button.

**Optimistic UI** (update before server responds):

```html
<button hx-post="/api/progress/${lessonSlug}/complete"
        hx-swap="outerHTML"
        hx-target="this"
        hx-disabled-elt="this"
        hx-indicator="#spinner">
  Mark Complete
</button>
<span id="spinner" class="htmx-indicator">Saving...</span>
```

Button disables immediately on click. Spinner shows until response arrives.

### Modal Dialogs

Load content on-demand:

**Trigger:**
```html
<button hx-get="/api/lesson/${slug}/preview"
        hx-target="#modal-content"
        hx-swap="innerHTML"
        onclick="document.getElementById('modal').showModal()">
  Preview Lesson
</button>

<dialog id="modal">
  <div id="modal-content">Loading...</div>
  <button onclick="this.closest('dialog').close()">Close</button>
</dialog>
```

**Server endpoint:**
```typescript
if (url.pathname.match(/^\/api\/lesson\/(.+)\/preview$/)) {
  const slug = url.pathname.match(/^\/api\/lesson\/(.+)\/preview$/)![1];

  const result = await db.execute(
    "SELECT title, description, content FROM lessons WHERE slug = ? LIMIT 1",
    [slug]
  );

  if (result.rows.length === 0) {
    return new Response("<p>Lesson not found</p>", { status: 404 });
  }

  const lesson = result.rows[0];

  // Return first 500 characters of content
  const preview = lesson.content.slice(0, 500) + "...";

  return new Response(`
    <h2>${lesson.title}</h2>
    <p>${lesson.description}</p>
    <div class="preview">${preview}</div>
    <a href="/${slug}">Read full lesson →</a>
  `, {
    headers: { "Content-Type": "text/html" },
  });
}
```

Click "Preview" → Opens modal → HTMX fetches preview HTML → Inserts into modal.

## Advanced Patterns

### Out-of-Band Swaps

Update multiple page sections from one request:

**HTML:**
```html
<div id="cart-count">0 items</div>

<button hx-post="/api/cart/add"
        hx-vals='{"item_id": "123"}'
        hx-target="#cart-feedback">
  Add to Cart
</button>

<div id="cart-feedback"></div>
```

**Server response:**
```typescript
// Returns multiple HTML fragments
return new Response(`
  <!-- Primary target -->
  <div id="cart-feedback">
    <p class="success">Added to cart!</p>
  </div>

  <!-- Out-of-band swap -->
  <div id="cart-count" hx-swap-oob="true">
    3 items
  </div>
`, {
  headers: { "Content-Type": "text/html" },
});
```

HTMX updates both `#cart-feedback` (primary target) and `#cart-count` (out-of-band swap) from a single request.

### Polling for Updates

Check for new content every 30 seconds:

```html
<div hx-get="/api/notifications"
     hx-trigger="every 30s"
     hx-swap="innerHTML">
  No new notifications
</div>
```

**Server:**
```typescript
if (url.pathname === "/api/notifications") {
  const userId = await getUserIdFromSession(req);

  const result = await db.execute(
    `SELECT message, created_at FROM notifications
     WHERE user_id = ? AND seen = FALSE
     ORDER BY created_at DESC
     LIMIT 5`,
    [userId]
  );

  if (result.rows.length === 0) {
    return new Response("No new notifications");
  }

  const html = `
    <ul class="notifications">
      ${result.rows.map(n => `
        <li>${n.message} <small>${formatTime(n.created_at)}</small></li>
      `).join("")}
    </ul>
  `;

  return new Response(html);
}
```

Polls server every 30 seconds. Updates content if there are new notifications.

### Request History (Back/Forward Support)

Add URL history for HTMX requests:

```html
<a href="/lessons/intro"
   hx-get="/api/lesson/intro"
   hx-target="#content"
   hx-push-url="true">
  Introduction
</a>
```

`hx-push-url="true"` adds entry to browser history. Back button works as expected.

## HTMX vs VanJS Trade-offs

| Aspect | HTMX | VanJS |
|--------|------|-------|
| **Bundle size** | 11KB | 1KB + app code (3-5KB) |
| **Server load** | More requests (HTML rendering) | Fewer (JSON APIs) |
| **SEO** | Excellent (HTML responses) | Good (SSR required) |
| **Interactivity** | Excellent for CRUD | Better for complex state |
| **Learning curve** | Minimal (HTML attributes) | Low (JavaScript knowledge) |
| **Offline support** | Poor (requires server) | Excellent (Service Workers) |

**Use HTMX when**: Server-driven apps, form-heavy UIs, SEO critical.

**Use VanJS when**: Complex client state, offline support, real-time updates.

**Use both**: HTMX for page structure, VanJS for interactive widgets (code playgrounds, visualizations).

## Hybrid Approach

Combine HTMX and VanJS:

```html
<!-- HTMX handles page navigation -->
<nav>
  <a href="/lessons" hx-get="/api/lessons" hx-target="#main" hx-push-url="true">
    Lessons
  </a>
</nav>

<main id="main">
  <!-- Server renders initial content -->
  <article id="lesson-content">
    <h1>Bun Fundamentals</h1>
    <p>...</p>
  </article>

  <!-- VanJS handles interactive code playground -->
  <div id="code-playground"></div>
  <script type="module">
    import van from "vanjs-core";
    import { CodePlayground } from "./components/playground.js";

    van.add(document.getElementById("code-playground"), CodePlayground());
  </script>
</main>
```

**Benefits:**

- HTMX: Page navigation, forms, search (server-rendered HTML)
- VanJS: Code execution, interactive charts (client-side state)

Best of both worlds. Minimal JavaScript for most UI, targeted reactivity where needed.

## Performance Comparison

**Test**: Load 100 lessons with infinite scroll

| Metric | Pure VanJS | Pure HTMX | Hybrid |
|--------|-----------|-----------|---------|
| Initial load | 12KB JS | 11KB JS | 12KB JS |
| Requests | 1 (JSON) | 10 (HTML) | 5 (HTML) |
| Time to interactive | 180ms | 220ms | 200ms |
| Server CPU | Low | Medium | Medium |
| Client CPU | Medium | Low | Low |

**HTMX advantage**: Less client-side computation. Server does rendering.

**VanJS advantage**: Fewer requests. Client does rendering.

**Hybrid advantage**: Balance. Critical path uses HTMX (fast TTI), enhancements use VanJS (rich interactivity).

## Common Pitfalls

### Forgetting hx-swap

```html
<!-- BAD - response disappears (defaults to innerHTML, but no target set correctly)
<button hx-get="/api/click">Click Me</button>
```

**Fix:** Always specify target and swap strategy:

```html
<button hx-get="/api/click" hx-target="#response" hx-swap="innerHTML">
  Click Me
</button>
```

### XSS Vulnerabilities

HTMX inserts HTML directly into DOM. **Never** trust user input:

```typescript
// VULNERABLE
const name = formData.get("name");
return new Response(`<p>Hello ${name}</p>`);  // XSS if name = <script>alert(1)</script>
```

**Fix:** Escape HTML:

```typescript
function escapeHtml(str: string): string {
  return str
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;")
    .replace(/'/g, "&#039;");
}

const name = escapeHtml(formData.get("name") as string);
return new Response(`<p>Hello ${name}</p>`);
```

Or use a template library with auto-escaping.

### Response Caching

Browsers cache GET requests. Stale data may appear:

```html
<!-- Might return cached response -->
<div hx-get="/api/notifications" hx-trigger="every 30s"></div>
```

**Fix:** Add cache headers:

```typescript
return new Response(html, {
  headers: {
    "Content-Type": "text/html",
    "Cache-Control": "no-cache, no-store, must-revalidate",
  },
});
```

Or use POST for non-idempotent actions.
