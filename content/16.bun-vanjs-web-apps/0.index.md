# Server-Side Web Apps with Bun and VanJS

Build fast, minimal web applications using Bun's all-in-one runtime and VanJS's 1KB reactive framework. No bloated toolchains, no framework sprawl—just modern web development done properly.

## Why This Stack

**Bun (v1.2+)**: All-in-one runtime replacing Node.js, npm, webpack, and Jest. Built-in TypeScript, JSX transforms, SQLite, PostgreSQL client, and S3 support. Installs packages 30% faster, serves HTTP 3x faster than Node.

**VanJS (v1.5)**: 1.0KB reactive framework with state management, no JSX compilation required. Async state derivations prevent unnecessary re-renders. Five functions total: `van.tags`, `van.add`, `van.state`, `van.derive`, `van.hydrate`.

**HTMX (v2.0)**: Declarative partial updates via HTML attributes. Reduces client-side JavaScript by 70-90% for typical interactive applications.

**AlpineJS (v3.14)**: Minimal reactive components for interactive widgets. Use when HTMX isn't sufficient, avoid when it is.

**LibSQL/Turso**: SQLite fork with concurrent writes, vector search, and edge deployment. Embedded replicas enable offline-first architecture.

**Three.js (r181)**: WebGL abstraction for 3D graphics. Educational visualizations, interactive diagrams, data exploration.

**WebGPU**: Native browser GPU access (85% desktop coverage as of 2025). Chrome 113+, Firefox 141+, Safari 26+. Compute shaders for parallel processing.


**Verify installation:**
```bash
bun --version  # 1.2.0 or higher
```

**Editor setup**: VSCode with Bun extension, or any editor with TypeScript support.

## Bun vs Python: Mental Model

| Python | Bun Equivalent | Notes |
|--------|----------------|-------|
| `python -m http.server` | `Bun.serve()` | Built-in HTTP server, no stdlib import |
| `uvicorn app:main` | `bun run server.ts` | Direct execution, no ASGI layer |
| `pip install` | `bun add` | 30% faster, lockfile in text format |
| `requirements.txt` | `package.json` | Semantic versioning, workspaces |
| `asyncio.run()` | `await fetch()` | Native async, no event loop setup |
| SQLite3 module | `Bun.sql` / `Database` | Built-in, no C extension |
| `psycopg2` | `Bun.sql` | Native PostgreSQL client |
| `dict`/`TypedDict` | `interface`/`type` | Static types checked at compile-time |

## Performance Expectations

From Python baseline:

- **HTTP serving**: 3-15x faster (Bun vs uvicorn/gunicorn)
- **Package installation**: 5-10x faster (bun vs pip)
- **Database queries**: 1.5-2x faster (native bindings vs Python DB-API)
- **File I/O**: 2-4x faster (system calls vs Python buffering)
- **JSON parsing**: 3-5x faster (JavaScriptCore vs Python C extensions)

These aren't synthetic benchmarks—you'll measure them yourself in Tutorial 1.

## Repository Structure

```
my-web-app/
├── client/
│   ├── app.js          # VanJS application
│   ├── styles.css      # Plain CSS, no preprocessor
│   └── index.html      # HTML shell
├── server/
│   └── index.ts        # Bun server
├── content/
│   └── lessons/
│       └── *.md        # Markdown files
├── data/
│   └── lessons.db      # SQLite database (built from markdown)
├── scripts/
│   └── build-content.ts  # Parse markdown into database
├── package.json
├── tsconfig.json
└── bunfig.toml
```

Simple, flat structure. No monorepo complexity unless you need it.
