# Zig Systems Programming

Deep dive into systems-level programming with Zig 0.15.2. No hand-holding, no abstractions you don't understand, just proper low-level engineering.

## What You'll Build

Seven progressively complex systems programs:

1. **zgrep** - CLI text search tool. File I/O, pattern matching, allocators.
2. **zjson** - JSON parser and formatter. Custom allocator, zero-copy parsing.
3. **zhttpd** - HTTP server from scratch. TCP sockets, concurrent connections, no frameworks.
4. **ztop** - TUI process monitor. Terminal manipulation, /proc parsing, real-time updates.
5. **zwin** - Native GUI window. Direct X11/Wayland, no toolkit bloat.
6. **zraster** - Software rasterizer. Triangle rendering, no GPU, pure maths.
7. **zalloc** - Custom memory allocator. Arena, pool, general-purpose allocation strategies.

## Why Zig

Python: High-level, GC, slow, batteries included
C: Low-level, manual everything, footguns everywhere, fast
Zig: Low-level, manual everything, fewer footguns, fast

Zig gives you C's performance with better ergonomics. No hidden control flow, no hidden allocations, no preprocessor nonsense. What you see is what runs.

## Zig vs Python: The Essentials

### Memory Management
Python: GC, reference counting, you rarely think about it
Zig: Manual allocation, comptime-known sizes when possible, you always think about it

### Error Handling
Python: Exceptions, try/except, stack unwinding
Zig: Error union types (`!T`), explicit handling, no stack unwinding

### Comptime
Python: Runtime everything, decorators sort of compile-time
Zig: Comptime execution, generics via comptime, types are values

### Build System
Python: setup.py, requirements.txt, pip, virtual envs
Zig: build.zig, self-contained, cross-compilation built-in

### Standard Library
Python: Massive, batteries included, C extensions hidden
Zig: Minimal, explicit, you see all the code

## Zig Fundamentals

### Allocators

```zig
const std = @import("std");

pub fn main() !void {
    var gpa = std.heap.GeneralPurposeAllocator(.{}){};
    defer _ = gpa.deinit();

    const allocator = gpa.allocator();

    const memory = try allocator.alloc(u8, 1024);
    defer allocator.free(memory);
}
```

Allocators are explicit. No malloc hiding behind the scenes. You choose: general-purpose, arena, fixed-buffer, whatever fits your use case.

### Error Handling

```zig
fn divide(a: i32, b: i32) !i32 {
    if (b == 0) return error.DivisionByZero;
    return @divTrunc(a, b);
}

pub fn main() !void {
    const result = divide(10, 0) catch |err| {
        std.debug.print("Error: {}\n", .{err});
        return;
    };
}
```

Errors are values. `!T` is error union type. No exceptions, no stack unwinding, just explicit control flow.

### Defer

```zig
fn processFile() !void {
    const file = try std.fs.cwd().openFile("data.txt", .{});
    defer file.close();  // Guaranteed to run when scope exits

    // Use file...
}
```

Defer executes code at scope exit. Like Python's context managers but more flexible.

### Comptime

```zig
fn max(comptime T: type) fn(a: T, b: T) T {
    return struct {
        fn inner(a: T, b: T) T {
            return if (a > b) a else b;
        }
    }.inner;
}

const maxInt = max(i32);  // Resolved at compile time
```

Comptime executes at compile time. Types are first-class values. Generics without templates.
